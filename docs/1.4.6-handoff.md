## 1. What's in the build

Five app-changing commits since 1.4.5 shipped (eight in total, the other three
being matchkit reports, the Superwall lock and this release cut). Full reasoning
is in each commit message; this is what a reviewer or a future reader needs to
know.

### The onboarding companion, and one visual language

Onboarding used to ask for a species with a segmented picker defaulting to
`.dog`, which nobody experienced as a decision — so the species every demo was
scored against was an assumption. It is now two animated animals you tap, with
nothing preselected.

The companion is drawn as SwiftUI shapes in a shared 220×258 design space with
absolute pivot coordinates, and runs three motion layers: `life` (breathing,
blinking, ear flicks) which never stops except under Reduce Motion, `mood` which
writes poses rather than animations so the verdict still reads with motion off,
and `accent` for one-shot reactions. `CompanionMood` mirrors the state-machine
inputs one-for-one, so swapping this for a Rive rig later is a view swap behind
an unchanged interface.

Alongside it, two surface roles applied app-wide. `surfacePrimary` was
`systemGray6` — Apple's grey ramp is blue-violet (#F2F2F7) and this app's ground
is a green-tinted #F0F9F4, so every card, chip and field sat on a hue fighting
its own background. Six views used `cardStyle()` while twenty hand-rolled a flat
fill, so the app ran two visual languages at once. Now `raisedSurface` for
anything above the page and `insetSurface` for anything in it, with no
hand-rolled filled surfaces left.

**This is why the screenshots were recut** — see §2.

### Duplicate allergen warnings — the fix an existing user feels

`synonyms.json` maps several label spellings onto one ingredient id, so a food
listing "Chicken" and "Chicken Broth" (both `ing_chicken`) showed the same
allergen warning twice, read "Chicken, Chicken" in the banner, and was penalised
twice for one ingredient.

`ScoreCalculator.distinctByIngredient` now collapses to one entry per ingredient
on the allergen and avoidance paths, keeping the *earliest* position on the
label because rank drives both the decay weight and the top-5 penalty tier —
keeping the later position would have quietly softened the penalty for exactly
the products that name the allergen most prominently. It is deliberately **not**
applied to the safety and processing paths, where three separate fillers really
are three fillers.

`ScoreBreakdown.allergenIngredientNames` guards the remaining case: two
genuinely different ingredient rows sharing a display name (`ing_chicken` and
`ing_chicken_fresh` are both "Chicken"). It lives on the model rather than in a
view because the scan result and the onboarding demo both need it, and when it
was derived independently in both, only one got de-duplicated.

### Onboarding is one path

Three exits are gone: the corner "Skip" on the search page, "Not now — finish
setup" on the profile page, and "Skip for now" on the avoidance groups page.

Two consequences worth knowing. The pet's name is now genuinely required — the
profile skip ended onboarding outright and **39% of finishers took it**, so with
it gone `continueFromProfile`'s validation is load-bearing rather than cosmetic.
And the search page's empty state now offers "Browse popular brands" rather than
leaving a user whose food is missing from the catalog with nothing but the query
that just failed.

### The keyboard could strand the user

Found only because the skip-removal test started failing once the software
keyboard was actually enabled — earlier screenshots were taken with a hardware
keyboard attached, so the software keyboard never rendered. With the keyboard at
y=583 on an 874pt screen, Continue sat at y=747, unhittable, along with the
second row of allergen chips. Survivable while onboarding had a skip; with the
skip gone it was the only way forward. There is now a Done button in the
keyboard toolbar, and a test asserting it restores reachability.

The CTA also jumped 20pt between pages — both result screens padded to `md`
where `standardChrome` uses `xxl`. All four onboarding pages now land the primary
button at the same height, asserted by a test.

### The rating prompt, and a new placement

The review prompt's arm was a `private static var`, so it died with the session
that made it, and the ask was made *after* the onboarding paywall rather than
before it — between them, most users were never asked at all. The arm now
persists, stored as the time it was armed so persistence and expiry are one
field, and the ask happens on the personalised result screen three seconds after
the score lands.

`search_by_name` is a new gated placement on the scanner's magnifying-glass
button — the moment a user reaches for text search instead of the camera. **No
campaign is attached yet**, so the feature block runs immediately and the sheet
opens exactly as before; attaching one later is a dashboard change rather than
another build.

## 2. Screenshots — recut, and why

**The 1.4.5 screenshots were stale the moment the surface rework landed.** Cards
went from `systemGray6` (#F2F2F7, mauve-grey) to #FCFEFD near-white, with new
green-black elevation shadows and a low-contrast on-hue border. Every card in
every shot changed. Shipping 1.4.5's art with 1.4.6's binary would have put a
grey-carded app on the store page and a white-carded app on the device.

Regenerated with `./Scripts/run_screenshots.sh` — 6.9" (1320×2868, iPhone 17 Pro
Max) and 6.5" (1284×2778, iPhone 14 Plus). The captions, the shot list and the
framing rules are unchanged from 1.4.5; only the app inside the frame is new.

`asc screenshots validate` reports 6 ready files and 0 errors for each size.

### The upload needs verifying, not trusting

**`asc screenshots upload` reported success for uploads that did not land.** The
6.5" run went locale by locale and printed a clean result for all twelve; a
pixel check afterwards found `01_HeroScore`, `02_UnsafeIngredients` and
`04_IngredientDetail` still showing 1.4.5 art in ten of them. A second pass per
locale fixed every one. The 6.9" run failed more honestly — it aborted partway
with an API timeout (`context deadline exceeded`), and a `--resume` of the
stranded file then failed its reorder step with "Can't Add/Remove Relationship
when reorder Set", which needed a plain `--replace` re-run to settle.

**`--skip-existing` is not a verification tool.** It compares checksums, and
Apple re-encodes some uploads, so it reports files as absent that are present
and correct — it claimed 47 of 72 6.5" assets were missing when the true number
was 30. Trusting it would have caused 17 pointless re-uploads and, worse, it is
equally capable of the opposite error.

**What actually verifies:** download the set and compare pixels.

```bash
asc screenshots download --version-localization "LOC_ID" --output-dir ./check
```

Then diff each file against `Screenshots/<size>-framed/`. Same art re-encoded by
Apple lands under a mean absolute difference of ~1; stale art from the previous
release sat at 6.8–17.6. The scripts used are in this session's scratchpad, but
the check is four lines of PIL and worth rewriting inline.

**Final state, verified this way: 144/144 assets** — 12 locales × 2 display
types × 6 shots — match the 1.4.6 art, with no missing assets.

Slot 3 now shows two allergen cards rather than one — "Allergen detected: Wheat"
floated over "Allergen detected: Chicken" — because the seeded scan trips both.
Each ingredient is named once, which is the shot the de-dupe has to hold up: this
is the screen where a food spelling one allergen two ways used to render the same
card twice.

## 3. Metadata

`metadata/version/1.4.6/`, 12 locales, seeded from 1.4.5.

**Description and keywords are carried forward unchanged.** Nothing in this
release changes what the app is or what it should rank for, and 1.4.5's
description (four sections, no feature bullets) and keywords (97/100 chars) were
tuned deliberately. Only `whatsNew` and `promotionalText` are rewritten.

The release notes lead with the allergen de-dupe rather than the companion. The
companion is the larger piece of work, but it exists only in onboarding, and
What's New is read almost entirely by people who already have the app and will
never see that screen again. The de-dupe is the change an existing user can
feel. The surface rework is second because it is app-wide; onboarding is third,
where a new user finds it.

`asc metadata validate --dir ./metadata` — 40 files, 0 issues. Every locale is
inside its limits; the tightest are the fr-CA and
Italian promotional texts at 159/170.

### Territories

Still **5 of 175** (US, CA, GB, AU, NZ), confirmed against
`asc pricing availability territory-availabilities --paginate`. See §5 — this is
now actionable in a way it was not at 1.4.5.

**On the 0-changed score-delta.** The de-dupe touches only the allergen and
avoidance paths, which need a pet profile that a catalog-wide sweep does not
have — so a zero here is the expected result, not evidence the change does
nothing. The behaviour it fixes is covered by
`testOneIngredientSpelledTwoWaysFlagsOnce` and
`testRepeatedIngredientDoesNotDoublePenaliseTheWatchList`, both of which fail
without it.

**`baseline-current.json` was regenerated as part of this release.** It was
still recording catalog 20260730 while the shipped catalog has been 20260901
since 1.4.5, so anything diffed against it reported the 1.4.5 catalog expansion
as though it were an uncommitted code change — a 10.2% churn number with 22
rating-label transitions that have already shipped. The 0-changed figure above
is against `after-negation-final.json`, which is the true 1.4.5 state.

**Not run:** server-side IPA validation (`asc xcode validate`). Unchanged from
1.4.5 — `altool` needs the API key as a `.p8` file and this machine keeps it in
the keychain, where only the REST client can reach it. Drop the key at
`~/.appstoreconnect/private_keys/AuthKey_35ABS9LGWB.p8` if you want that check.
