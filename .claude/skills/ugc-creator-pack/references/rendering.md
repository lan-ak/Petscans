# Rendering the .docx

Creators need a document they can open, not markdown. Every pack is generated by a script so
it can be regenerated when scores move.

## Setup

python-docx lives in the campaign venv:

```bash
# already installed; recreate only if missing
cd PetScans-Meta-Campaign && python3 -m venv venv && ./venv/bin/pip install python-docx
```

## Folder convention

```
PetScans UGC/
├── ugc_docx.py                          shared layout — import it, never fork it
├── Ellie Hofstedt - Cat Rescue/
│   ├── PetScans-UGC-Scripts-Ellie-Hofstedt.docx
│   ├── build-ellie-pack.py
│   └── ugc-scripts-cat-rescue.md
└── Kara Robinson - Farm and Dog/
    ├── PetScans-UGC-Scripts-Kara-Robinson.docx
    ├── build-kara-pack.py
    └── ugc-scripts-kara-dog.md
```

Name the folder `<Firstname Lastname> - <Angle>` and the .docx with the creator's name — it
gets emailed and downloaded, so the filename has to identify itself out of context.

Start a new pack by copying the nearest existing `build-*-pack.py` and replacing the copy.

## The `ugc_docx` API

```python
import sys; from pathlib import Path
sys.path.insert(0, str(Path(__file__).resolve().parent.parent))
from ugc_docx import (bullets, callout, cover, cut_label, heading, new_doc,
                      rich, rule, script_header, shotlist, table, vo)
```

`**bold**` works inline in every text argument.

| Call | Use |
|---|---|
| `new_doc()` | margins, Calibri, spacing |
| `cover(doc, title, subtitle, [lines])` | first page |
| `heading(doc, text, size=, before=, after=)` | section head |
| `rich(doc, text, size=, color=, after=)` | paragraph |
| `bullets(doc, [items])` | bulleted list |
| `rule(doc)` | hairline divider |
| `table(doc, headers, rows, widths=, bold_col=)` | product sheet |
| `script_header(doc, n, title, meta, onscreen)` | script title + shaded facts box |
| `cut_label(doc, "30-second version")` | accent sub-head |
| `shotlist(doc, [(time, visual, audio)])` | the 30s shot table |
| `vo(doc, beat, text)` | one timed 60s beat |
| `callout(doc, text, fill="FDF3F1")` | warning box (use the pink fill for these) |

## Document order

1. Cover — what the pack is, and up front that **no products are required**
2. **Before you shoot** — what they need; which of *their* named formats each script maps to
3. **Six rules for what you say on camera** — the honesty rules in plain language
4. **The five products** — search term, general score, warnings the app shows
5. Five scripts, `doc.add_page_break()` between each
6. **What we need from you** — every `[BRACKET]` slot as a checklist
7. **Filming notes**

## Keep engineering material out

The creator's document contains no GTINs, no matchkit commands, no file paths, and no
discussion of matcher behaviour. Translate constraints into performance instructions:

> "Only Scripts 1 and 5 can blame chicken. On the others the app logs the by-product
> differently, so use corn, soy or wheat. You can still read 'chicken by-product meal' off
> the ingredient list — that's just reading the label, and it's true."

All the reasoning goes in the internal `ugc-scripts-<angle>.md` alongside it.

## Verify after building

```bash
../../PetScans-Meta-Campaign/venv/bin/python -c "
from docx import Document
d = Document('PetScans-UGC-Scripts-<Name>.docx')
t = '\n'.join(p.text for p in d.paragraphs)
print('tables', len(d.tables))
for s in ['Script 1','Script 5','What we need from you']:
    print('OK' if s in t else 'MISS', s)"
```

Then `open` it and look at it. If Word has the file open, a `~$`-prefixed lock file blocks
`rmdir` — delete the lock, and tell the user to reopen from the new path if you moved or
renamed a doc they had open.
